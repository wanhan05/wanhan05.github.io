ChainSense treats the Ethereum blockchain as a global, event-driven distributed system. The project transforms raw transaction data into interpretable wallet behavioral features and applies unsupervised machine learning to identify distinct wallet archetypes — with the goal of making on-chain behavior legible as a signal for financial analysis.

1. Data Pipeline Architecture

Bronze-Silver-Gold Architecture

We implemented a three-layer data architecture to progressively transform raw blockchain data into model-ready features.

LayerContents
Bronze (raw)Append-only raw data from Alchemy API: blocks, transactions, receipts, event logs
Silver (decoded)Semantic decoding of smart contract interactions: ERC-20 transfers, DeFi events, NFT mints
Gold (features)Wallet-level aggregated features optimized for ML — one row per unique wallet

Data Collection

We collected 10,000 consecutive Ethereum blocks (blocks 24,396,337 to 24,406,337), representing approximately 33 hours of blockchain activity — sufficient behavioral density while remaining computationally tractable.

  • Total transactions: 3,888,735
  • Unique wallets analyzed: 2,847,621
  • Average transactions per block: 389
  • Time span: ~33 hours

2. Feature Engineering

We engineered 15 features across 4 conceptual categories, each capturing distinct aspects of wallet behavior. Feature selection prioritized interpretability and orthogonality.

Activity Metrics

FeatureRationale
tx_countFundamental activity metric — separates high-volume entities (bots, exchanges) from casual users
active_blocksTemporal consistency — distinguishes persistent activity from burst events
tx_per_blockActivity intensity — reveals automated systems operating at high throughput
burstinessσ/μ of transactions per block — low values indicate consistent automation, high values suggest sporadic human activity

Value Flow Metrics

FeatureRationale

eth_recvTotal ETH inflow — accumulation behavior
eth_net_flowNet position — positive = accumulators, negative = distributors
avg_tx_valueTransaction size preference — distinguishes retail from institutional behavior

Gas Behavior Metrics

FeatureRationale

avg_gas_price_gweiUrgency and wealth indicator — higher prices signal time-sensitive or high-value operations

Interaction Pattern Metrics

FeatureRationale

unique_contractsDeFi/protocol engagement breadth
contract_interaction_rateProportion of contract calls vs simple transfers
counterparty_concentrationHerfindahl index — measures how focused vs diversified the wallet's connections are

3. Feature Analysis

Correlation Analysis

Key findings from pairwise Pearson correlation across all 15 features:

  • Strong positive correlations (r > 0.9): tx_count ↔ unique_counterparties (0.96), tx_count ↔ tx_per_block (0.92), eth_sent ↔ eth_recv (0.98)
  • Gas behavior cluster: avg_gas, avg_gas_price_gwei, and total_gas_spent_eth show moderate intercorrelation (0.67–0.89)
  • Orthogonal features: burstiness shows weak correlation with most features — a valuable independent signal
  • Contract interaction independence: contract_interaction_rate is relatively uncorrelated with activity metrics, capturing a distinct behavioral dimension

Principal Component Analysis

Applied after log-transforming heavy-tailed features and robust scaling:

  • PC1 (65.8% variance) — dominated by tx_per_block (loading: 0.85), representing activity scale
  • PC2 (25.2% variance) — dominated by eth_net_flow (loading: 0.82), representing accumulation vs distribution
  • PC3 (5.0% variance) — mix of contract interaction and burstiness features
  • Top 3 PCs capture 96.0% of total variance — exceptional dimensionality reduction

5. Conclusions & Limitations

Carefully engineered behavioral features can reveal interpretable wallet archetypes from raw blockchain transaction data. Our 15-feature representation achieved exceptional dimensionality reduction and good clustering performance, with discovered clusters mapping directly to known Ethereum infrastructure.

Limitations

  • Sample size: 15 wallets is sufficient for methodology validation but larger samples would enable more nuanced archetype discovery
  • Temporal scope: 33-hour window captures short-term behavior but may miss longer-term patterns
  • Feature redundancy: High correlations between eth_sent/eth_recv and tx_count/unique_counterparties suggest further dimensionality reduction opportunities
  • Event decoding: Silver layer analysis was not fully implemented in this iteration

Future Directions

  • Extended temporal analysis across multiple block windows to study behavioral stability
  • TF-IDF encoding on event sequences and graph-based wallet features
  • DBSCAN/HDBSCAN for density-based clustering — more appropriate for irregular cluster shapes
  • GPU-accelerated pipeline using RAPIDS/cuML — DBSCAN 50–500× speedup at scale
  • Trading signal development from behavioral cluster transitions

Technical Appendix

Key Formulas

Burstiness:
  burstiness = σ(transactions_per_block) / (μ(transactions_per_block) + ε)

Counterparty Concentration (Herfindahl Index):
  concentration = Σ(counterparty_share²)

Contract Interaction Rate:
  rate = count(tx with input_data ≠ 0x) / total_sent_transactions

Processing Pipeline

Web3.py + Alchemy API  →  Bronze layer (.parquet)
Pandas aggregations    →  Gold layer feature matrix
Log transformation (log1p) on heavy-tailed features
RobustScaler (preferred over StandardScaler for outlier robustness)
PCA for visualization and dimensionality reduction
K-Means (k=3, random_state=42, n_init=20)
